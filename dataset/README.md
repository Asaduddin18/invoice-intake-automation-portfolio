# Synthetic supplier invoice dataset v1

50 original searchable PDFs for learning and testing Gmail invoice intake, DeepSeek extraction, configurable review, and Xero draft supplier bills. No Gmail, Xero, model API, or paid service was connected during creation.

## Contents and coverage

- `tuning/`: 30 PDFs and individual ground-truth JSON files.
- `evaluation/`: 20 held-out PDFs and individual JSON files. Do not use these for prompt tuning.
- `ground_truth.json`, `manifest.csv`, `supplier_master.json`: expected fields, scenario outcomes, split membership, and fictional supplier identities.
- `generate.py`: editable deterministic generator; `verify.py`: independent arithmetic, text extraction, split and page-bound checks plus rendered contact sheets.

| Scenario | Files |
| --- | ---: |
| Valid original invoices | 34 |
| Missing invoice number, supplier identity, invoice date, or due date | 4 |
| Incorrect printed subtotal, tax, or total | 4 |
| Unknown fourth supplier | 2 |
| Duplicate submissions, including four re-laid-out copies | 6 |

Three original layout families vary header order, field labels, table column order, typography/colors, and date formats. Examples contain 1-5 lines, three longer 28-line documents, fractional quantities, varied payment terms, optional purchase-order references, 0% or 20% exclusive test tax, and multi-page pagination where needed. All amounts use GBP and Decimal rounding to two places. Dates span several months. Missing due dates are held under this dataset's policy; a client might instead provide an agreed default.

Known suppliers: Alder Packing Supplies, Bracken Industrial Components, Cedar Facilities Services. Dovetail Trade Supplies is intentionally unknown. All bill Northmere Distribution. Names and addresses are invented test identities; `.example` email domains cannot receive mail. No bank numbers, registration identifiers, signatures, or real customer records are included.

The dataset is grounded in common invoice fields and layout conventions from the sources below. It is independently authored, not an export produced by Xero/QuickBooks, and does not reproduce their branding. These fixtures are not tax-compliant commercial documents. The tax rates are explicit test assumptions, not tax advice.

## Ground truth and use

Every PDF has a sibling JSON with printed fields, calculated totals, expected validation outcome and reason, layout, and duplicate relationship. Monetary values are strings to avoid floating-point ambiguity. Missing values are null. Corrupt arithmetic remains printed in the PDF; `calculated_total` retains the correct line-based result.

Run duplicate scenarios in original-then-copy order, and also copy-then-original. Exactly one draft should result for each duplicate family. `duplicate_if_original_processed` is conditional on processing history, not a document property. The two splits share suppliers/layouts and test variation within familiar families; they do not measure generalization to unseen layouts. A held-out split generated by the same code is still synthetic evaluation.

Keep JSON, filenames, scenario labels, and the manifest out of model inputs. Send only invoice content and permitted business context. Filename numbering is for test administration. Evaluate field extraction before correction, financial checks, supplier mapping, duplicate results, and destination correctness separately. The visible demo footer is a known synthetic artifact.

## Recreate and verify

Use Python 3 with `reportlab`, `pdfplumber`, and `Pillow`, and `pypdfium2` for rendering. Version requirements are in `requirements.txt`.

```sh
python generate.py
python verify.py --render-dir /tmp/invoice-dataset-review
```

Generation overwrites this dataset's matching generated files. Commit any deliberate fixture edits first. Verification renders every page and writes a machine-readable report. Inspect every contact sheet and use full-size pages when checking details. Generation and verification need no network or credentials.

Initial QA: 50 PDFs were rendered and inspected through contact sheets; searchable text, page boundaries, printed numeric fields, line descriptions, line arithmetic, intentional total errors, and duplicate split isolation were checked. The complete dataset was checked as PDF fixtures. Model extraction was evaluated separately on 20 selected documents; see ../docs/case-study.md. See `verification.json` for machine checks.

## Research sources

Reviewed 2026-11-01. Used for invoice field conventions and layout ideas only; no third-party invoice is redistributed.

- [Xero UK invoice template](https://www.xero.com/uk/templates/invoice-template/): header identity, dates, itemized charges, totals.
- [Xero template fields](https://central.xero.com/0/article/Fields-you-can-insert-into-a-custom-template-UK): contact, quantity, references, and optional fields.
- [QuickBooks invoice templates](https://quickbooks.intuit.com/global/invoice-template/): variation in item/service presentation.
- [QuickBooks public sample PDF](https://digitalasset.intuit.com/render/content/dam/intuit/sbseg/en_row/quickbooks/web/content/sbseg-en-row-2023-invoice-template-editable.pdf): invoice number, issue/due dates, and terms as separate fields.
- [Source Upwork brief](https://www.upwork.com/jobs/~022116696456487344298): varying PDF layouts, structured billing records, accounting writes, monthly reporting, and privacy. It requests Claude; this portfolio intentionally substitutes DeepSeek.

## Boundaries and extensions

This set covers text-based PDFs. It does not cover scans/OCR, handwriting, malformed PDFs, encrypted attachments, credit notes, tax-inclusive pricing, mixed tax rates, discounts, foreign currencies, or corrected invoice versions. Add those as explicitly labeled extension suites after the core workflow works. No finite set covers all invoice formats. Exception test cases intentionally extend beyond the three known supplier families without expanding automatic posting eligibility.
